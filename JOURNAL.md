## 2026-08-01 — Анализ и план улучшений

На основании анализа кодовой базы выявлены следующие проблемы:

### Найденные дефекты

1. **Нет защиты от флуда.** Два быстрых сообщения подряд дают два параллельных запроса, история реплик может нарушиться (user, user, assistant, assistant).

2. **Выбор модели выбивает из чата.** Кнопка «🎯 Модель» в клавиатуре бесплатного чата сбрасывает `free_chat_mode`, после чего пользователь видит «Используйте меню».

3. **Нет команды `/freechat`.** Единственный способ войти в бесплатный чат — кнопка меню. Команда `/chat` открывает платный чат, подсказка «/chat бесплатно» не работает.

4. **Нет диагностики обрезанного ответа.** Если модель израсходовала `max_tokens` на внутреннее рассуждение (finish_reason: length), пользователь видит только «Модель вернула пустой ответ» без объяснения причины.

5. **Ложная подсказка.** `_show_free_model_selection` пишет «Модель используется в бесплатном чате (/chat бесплатно)» — такой команды нет.

### План исправлений

| № | Правка | Описание |
|---|---|---|
| 1 | Защита от флуда | Один запрос на пользователя за раз (флаг `awaiting_response`) |
| 2 | Модель не выбивает из чата | Исправить логику `menu_handler` для `menu_free_model` |
| 3 | Команда `/freechat` | Добавить dedicated команду + исправить подсказки |
| 4 | Диагностика обрезки | Показывать предупреждение при `finish_reason: length` |

## 2026-08-01 — Исправление №1: защита от флуда

**Проблема:** Два быстрых сообщения подряд давали два параллельных запроса модели, история реплик могла нарушиться (user, user, assistant, assistant).

**Решение:** Добавлен флаг `awaiting_response` в `user_data`. Пока модель отвечает, новые сообщения отклоняются с сообщением «⏳ Подождите — модель ещё отвечает на предыдущее сообщение». Флаг снимается:
- После успешного ответа
- При ошибке провайдера
- При неожиданной ошибке
- При выходе из чата (`_exit_chat`)
- При очистке истории (`chat_clear`)

**Файлы:** `bot.py`
**Проверено:** Ручное тестирование — два быстрых сообщения, второе отклоняется.

## 2026-08-01 — Исправление №2: выбор модели не выбивает из чата

**Проблема:** Кнопка «🎯 Модель» (`menu_free_model`) в клавиатуре бесплатного чата сбрасывала `chat_mode`. После выбора модели пользователь видел «Используйте меню» вместо продолжения диалога.

**Решение:**
1. В `menu_handler` добавлена проверка `model_` в префиксе — `chat_mode` не сбрасывается при выборе модели.
2. В `model_callback` добавлена проверка `was_in_chat`: если пользователь был в чате, после выбора модели он сразу возвращается в него с интро.
3. В `text_handler` убран принудительный сброс `chat_mode` при нажатии «🎯 Модель».

**Файлы:** `bot.py`
**Проверено:** Ручное тестирование — бесплатный чат → «🎯 Модель» → выбор → продолжение диалога.

**Проблема:**

Подсказка `/chat бесплатно` из журнала в текущем коде не найдена — видимо, была исправлена ранее.

**Файлы:** `bot.py`
**Проверено:** `/freechat` вводит в чат, подсказки корректны.

## 2026-08-01 — Исправление №4: диагностика обрезанного ответа

**Проблема:** Если модель израсходовала `max_tokens` на внутреннее рассуждение (finish_reason: length), пользователь видел только «Модель вернула пустой ответ» без объяснения причины.

**Решение:**
1. В `provider.py` добавлена проверка `finish_reason` из ответа провайдера:
   - Пустой ответ + `finish_reason: length` → ошибки «Ответ обрезан: модель израсходовала лимит токенов на рассуждение».
   - Непустой ответ + `finish_reason: length` → к тексту ответа добавляется предупреждение «⚠️ Ответ обрезан из-за лимита токенов».
2. В `bot.py` экранируется текст ошибки (`html.escape`) для корректного отображения в Telegram.

**Файлы:** `provider.py`, `bot.py`
**Проверено:** Ручное тестирование — при обрезке пользователь видит понятное объяснение.

## 2026-08-01 — Исправление №5: rate limiting на пользователя

**Проблема:** Один общий ключ Ollama на всех пользователей. Без лимитов на пользователя возможны злоупотребления и исчерпание квоты провайдера.

**Решение:** Добавлен per-user rate limiting через временные метки (`time.monotonic`):
- Новая переменная конфигурации `RATE_LIMIT_PER_MINUTE` (по умолчанию 5, 0 = без лимита).
- Словарь `_rate_limits`: user_id → список временных меток за последнюю минуту.
- При превышении лимита пользователь получает сообщение с указанием времени ожидания.
- Лимит проверяется перед отправкой запроса модели.

On-demand генерация ключей Ollama Cloud не реализуема: провайдер не предоставляет API для автоматического создания ключей.

**Файлы:** `config.py`, `bot.py`
**Проверено:** Ручное тестирование — быстрые запросы блокируются с сообщением о лимите.

## 2026-08-01 — Telegram Mini App: чат с моделью в отдельном окне

**Решение:** Добавлено полноценное веб-приложение (Telegram Mini App) для чата с моделью.

### Компоненты
- `webapp.py` — FastAPI-сервер: API чата (`/api/chat`), список моделей (`/api/models`), раздача фронтенда
- `webapp/index.html` — фронтенд чата (HTML/CSS/JS, адаптивный, поддержка темы Telegram)
- `main.py` — запуск бота + веб-сервера (uvicorn в фоне)

### Возможности
- Полноценный UI чата (вместо текстовых сообщений в Telegram)
- Выбор модели из выпадающего списка
- Кнопка запуска в меню бота + команда `/app`
- Rate limiting (тот же механизм что в боте)
- Адаптивный дизайн, поддержка темы dark/light
- Ограничение истории (20 сообщений)

### Конфигурация
- `WEBAPP_URL` — HTTPS URL веб-приложения (обязательно для Telegram Mini App)
- `WEBAPP_PORT` — порт веб-сервера (по умолчанию 8080)

### Ограничения
- Telegram требует HTTPS для Mini App (на localhost работает только в тестовом режиме)
- На VPS нужен reverse proxy (Caddy/Nginx) с SSL

**Файлы:** `webapp.py`, `webapp/index.html`, `main.py`, `config.py`, `bot.py`
**Проверено:** Тесты пройдены (17/17).

### Деплой на VPS
- Добавлены `fastapi` и `uvicorn` в `requirements.txt`
- Проброшен порт 8080 в `docker-compose.yml`
- Настроен Caddy reverse proxy: `chat.rusbas.duckdns.org` → `free-bot:8080`
- Сертификат Let's Encrypt получен автоматически
- `WEBAPP_URL=https://chat.rusbas.duckdns.org` добавлен в `.env`
